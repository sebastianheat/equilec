1. Resumen ejecutivo

El Cotizador EQUILEC es una aplicación web que permite a los vendedores armar cotizaciones (cliente, productos, costos, márgenes, moneda, condiciones) y generar un PDF profesional. Cada cotización se guarda en una base de datos propia y, además, se sincroniza con Heat Suite (HIT / GoHighLevel) para el seguimiento comercial automatizado.

Originalmente vivía en Netlify. Se migró a una nueva infraestructura sobre GitHub + Vercel + Neon (PostgreSQL), con su base de datos aislada e independiente, conservando todo el histórico (44 cotizaciones, folios 1501–1545, y los usuarios).

2. Arquitectura general

Aplicación serverless: un frontend estático + funciones de backend bajo demanda + base de datos Postgres administrada. La cotización completa vive en la base propia; HIT recibe una vista comercial.

4. Cómo funciona el cotizador

Autenticación y roles

  • Vendedores entran al cotizador (index.html) con correo + contraseña. La sesión usa un token firmado (HMAC) de 30 días — sin estado en servidor.
  • Cada usuario tiene un tipo de acceso (access_role):
    • Admin ve todas las cotizaciones y administra usuarios.
    • Vendedor crea y ve solo las suyas; no administra usuarios.
  • El panel admin (/admin) está protegido por una contraseña maestra (EQUILEC_ADMIN_PASSWORD) e incluye el buscador global y la gestión de usuarios.

Motor de precios (regla de negocio clave)

El vendedor ingresa costo y margen %; el precio de venta se calcula solo y queda bloqueado (no editable). El margen es sobre el precio de venta: precio = costo ÷ (1 − margen%). Ej.: costo 100 con 20% → 100 / 0,8 = 125.
  • Redondeo: todos los valores se redondean hacia arriba, sin decimales (por producto, total e IVA), tanto en pantalla como en el PDF.
  • Moneda: CLP / USD / EUR, elegible por cotización; aplica a toda la cotización y al PDF.
  • IVA: 19% incluido siempre (en cualquier moneda). El PDF ya no indica "valores netos / no incluyen IVA".

Productos, buscador y campos

  • Cada producto tiene SKU y N° de parte (interno, p. ej. para Codelco): el N° de parte se ve internamente pero no aparece en el PDF del cliente.
  • Campos de cabecera: Referencia y N° OT (orden de trabajo).
  • Buscador (panel admin y barra lateral del vendedor): encuentra por cliente, RUT, referencia, OT, SKU, N° de parte y vendedor.

5. Modelo de datos (Neon · PostgreSQL)

TablaContenido
cotizacionesUna fila por folio. Columnas: number (folio), status, client, items, terms, vendor, totals (JSONB), created_by, ot, fechas. Los productos (SKU, N° parte, costo, margen, precio) viven dentro de items.
usersVendedores/admin: email, nombre, cargo (sale en el PDF), access_role (admin/vendedor), teléfono, hash de contraseña (scrypt), activo.
countersCorrelativo de folios (arranca en 1501). Reserva atómica del siguiente N°.

La base es independiente de la del cotizador anterior: se copió un snapshot, sin tocar la original.

7. Integración con HIT (Heat Suite / GoHighLevel)

La cotización completa vive en la base del cotizador. HIT recibe una vista comercial para el seguimiento. La sincronización es de una vía (cotizador → HIT) y ocurre al crear la cotización (no en cada edición, para no duplicar oportunidades).

Qué se crea en HIT

En HITDetalle
ContactoEl cliente. Upsert por email/teléfono (no duplica).
OportunidadPipeline Oportunidades de Venta → etapa Solicita Cotización. Incluye valor, dueño = el vendedor (mapeo correo → usuario de HIT), nombre COT-1546 · Cliente y tags.
NotaEn la ficha del contacto: folio, OT, referencia, moneda, total y un link que abre la cotización completa.

Tags que deja el cotizador (los usan los Workflows)

  • cotizador — origen.
  • moneda-clp / moneda-usd / moneda-eur.
  • cotizacion-alto-valor — se aplica cuando el total supera el umbral: CLP ≥ 2.000.000, USD ≥ 2.000, EUR ≥ 2.000. El Workflow de seguimiento prioritario filtra por este tag (sin hacer cálculos de moneda).

Conexión técnica

Vendedor guarda cotización │ ▼ [ /api/save ] ──► Neon (equilec-db) ← fuente de verdad │ └──► API de HIT (services.leadconnectorhq.com, v2) módulo api/_ghl.mjs ├─ upsert Contacto ├─ crea Oportunidad (pipeline · etapa · valor · dueño · tags) └─ agrega Nota con link
  • Autenticación: un Private Integration Token de la sub-cuenta de HIT, guardado como variable de entorno en Vercel (GHL_API_TOKEN, GHL_LOCATION_ID) — no está en el código ni en GitHub.
  • Resiliente: si HIT estuviera caído, la cotización igual se guarda; solo no sincroniza esa vez.
  • Automatizaciones (24 h WhatsApp / 48 h correo + mover etapa) se construyen como Workflows dentro de HIT, usando los tags anteriores. El cotizador solo deja los datos listos.

8. Migración e historial

  • Origen: proyecto en Netlify (cotizadorequilecbyheat) con Netlify Functions + Netlify DB (Neon).
  • Se portaron las funciones a Vercel, se migró el driver de base de datos y se creó una base Neon nueva y aislada con un snapshot de los datos (44 cotizaciones + 5 usuarios + correlativo).
  • La base original quedó intacta (solo lectura durante la copia).

10. Seguridad

  • Contraseñas de usuario con hash scrypt (salt por usuario); nunca se guardan en texto plano.
  • Sesiones con token HMAC firmado; los secretos viven solo en variables de entorno.
  • El token de HIT es de tipo Private Integration (revocable) y no se versiona en el repositorio.
  • Aislamiento por rol en el backend: un vendedor no puede leer cotizaciones de otros vía API.
